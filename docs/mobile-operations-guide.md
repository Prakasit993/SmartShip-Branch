# Mobile Operations Guide – SmartShip

---

## 1) เป้าหมายของคู่มือ

เอกสารนี้ใช้กำหนดแนวทางให้ SmartShip ใช้งานได้ดีบนสมาร์ตโฟนสำหรับงานหน้าสาขา โดยเน้น:

- กรอกข้อมูลเร็วด้วยมือเดียว
- สแกน QR ได้เสถียรจากกล้องมือถือ
- ทำงานได้แม้เครือข่ายไม่เสถียร
- ลดโอกาสกรอกผิดในหน้าจอขนาดเล็ก

---

## 2) Mobile UX Baseline (ควรทำทันที)

### หน้าจอและองค์ประกอบ

- ใช้ layout แบบ single-column เป็นค่าเริ่มต้นที่ความกว้าง < 768px
- ขนาดปุ่มหลักขั้นต่ำ 44x44px
- ใช้ฟอนต์อย่างน้อย 16px สำหรับ input เพื่อลดการ zoom อัตโนมัติบน iOS
- เว้นระยะระหว่างปุ่มอันตราย (`ลบ`, `ยกเลิก`) กับปุ่มหลัก (`บันทึก`, `ยืนยัน`)

### ฟอร์มกรอกข้อมูล

- เปิด keyboard ตามประเภทข้อมูล:
  - เบอร์โทร: `type="tel"`
  - จำนวนเงิน/น้ำหนัก: `inputMode="decimal"`
  - รหัสไปรษณีย์: `inputMode="numeric"`
- แตกฟอร์มยาวเป็น step สั้น ๆ (ผู้ส่ง -> ผู้รับ -> ตรวจสอบ)
- ใช้ sticky action bar ด้านล่าง: `บันทึกฉบับร่าง`, `ถัดไป`, `ยืนยัน`

### การสแกน QR

- มีปุ่ม "เปิดกล้อง" และ "กรอกรหัสแทน" เสมอ (fallback)
- แสดงกรอบสแกนใหญ่กลางจอ และข้อความแนะนำระยะห่าง
- เมื่อสแกนสำเร็จให้สั่นเครื่อง (haptic) และมีเสียงสั้นเพื่อยืนยัน

## 3) Flow ที่เหมาะกับมือถือ

### UC-01: สร้าง Shipment Draft

1. หน้าแรกมีปุ่มเดียวชัดเจน: `สร้างพัสดุ`
2. กรอกข้อมูลทีละส่วน (stepper):
   - Step 1: ผู้ส่ง (ชื่อ/เบอร์)
   - Step 2: ผู้รับ (ชื่อ/เบอร์/ที่อยู่)
   - Step 3: ตรวจสอบ + บันทึก
3. หลังบันทึกให้แสดง QR เต็มจอ พร้อมปุ่ม:
   - `แสดงให้ลูกค้า`
   - `บันทึกภาพ QR`
   - `สร้างรายการใหม่`

### UC-02: สแกนและยืนยันเข้า J&T

1. เปิดเมนู `สแกนรับเข้า`
2. กล้องทำงานทันที และรองรับสแกนต่อเนื่อง
3. หลังพบ shipment แสดงเฉพาะข้อมูลจำเป็นบนมือถือ:
   - ผู้รับ
   - ปลายทาง
   - น้ำหนัก
   - COD
4. ปุ่มหลักด้านล่างจอ: `ยืนยันและส่งเข้า J&T`

---

## 4) ความทนทานต่อเน็ตไม่เสถียร

- แสดงสถานะเครือข่ายทุกหน้า: `ออนไลน์` / `กำลัง reconnect`
- เมื่อกดบันทึกแล้ว offline ให้เก็บใน local queue และแสดง badge `รอส่ง`
- เมื่อออนไลน์กลับมา ให้ sync อัตโนมัติและแจ้งผลทีละรายการ
- คำสั่งสำคัญ (`ยืนยันเข้า J&T`) ต้องมี idempotency key เพื่อกันข้อมูลซ้ำ

---

## 5) Mobile Security ที่ควรมี

- Auto logout เมื่อไม่มีการใช้งานเกิน 10-15 นาที
- ซ่อนข้อมูลบางส่วน (เช่น เบอร์โทร) เมื่อหน้าจอ idle
- ห้ามเก็บ secret/service key ในฝั่ง client
- บังคับ HTTPS และ secure cookie เสมอ

---

## 6) Technical Recommendations (Next.js)

- รองรับ PWA เพื่อเข้าใช้งานแบบ app-like และ cache หน้าใช้งานหลัก
- โหลด component ที่ใช้กล้องแบบ dynamic import เพื่อลด initial bundle
- ใช้ optimistic UI เฉพาะ action ที่ย้อนกลับได้
- ตั้ง performance budget บน mobile:
  - LCP < 2.5s (4G)
  - TTI < 3.5s

---

## 7) Checklist สำหรับปรับระบบให้ "พอดี" กับมือถือ

- [ ] ปรับทุกหน้า workflow หลักเป็น single-column ที่จอเล็ก
- [ ] เพิ่ม sticky bottom action bar ในหน้า form/scanner
- [ ] รองรับ fallback ป้อนรหัสแทนการสแกน
- [ ] ลด field ที่ไม่จำเป็นในหน้ามือถือ (เก็บในโหมดขยาย)
- [ ] เพิ่ม offline queue + retry สำหรับ draft save
- [ ] เพิ่ม loading state, success state, error state ที่อ่านง่าย
- [ ] ทดสอบจริงบน Android และ iPhone อย่างน้อยฝั่งละ 1 รุ่น

---

## 8) ลำดับการทำงานที่แนะนำ

1. ปรับ UX หน้า UC-01 และ UC-02 ให้ mobile-first ก่อน
2. ทำ scanner fallback + network status
3. เพิ่ม offline queue สำหรับ draft
4. ค่อยเพิ่ม PWA และ dashboard view บนมือถือ
